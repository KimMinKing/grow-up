# 성장·신수 앱 설계 청사진 v0.1 (이전안)

> 이 문서는 게임 비중이 과했던 이전안이다. 최신 설계와 개발 순서는 [MASTER_PLAN.md](MASTER_PLAN.md)를 따른다.

작성: 2026-10-30. 구현 전 검토용. 확정된 요구와 조정 가능한 초기 수치를 구분한다. 제품 결정의 이력과 도감 후보는 [PRODUCT_BLUEPRINT.md](PRODUCT_BLUEPRINT.md)를 함께 본다.

## 1. 제품 정의와 성공 기준

**약속:** 사용자가 막연한 성장 목표를 적으면 AI가 실행 가능한 로드맵 3개를 제안한다. 사용자는 하나를 선택하고 오늘의 작은 행동을 완료한다. 현실의 진척은 목표 기록과 상태창에 남고, 신수의 태동→각성→초월 및 파견·수집으로 보인다.

**하루의 핵심 고리:** 오늘의 퀘스트 확인 → 쉬움/보통/도전 중 선택 → 완료 → 현실 진행률과 신수 반응 확인 → 스쿼드 파견 → 나중에 보상 수령. 뽑기는 가끔 얻는 추가 보상이다.

**성공 판단:** 사용자가 첫 목표를 10분 이내에 만들고 첫 퀘스트를 시작할 수 있는가, 2주 동안 자기 상황에 맞춰 반복할 수 있는가, 로드맵의 한 단계를 실제로 끝낼 수 있는가, 앱 안의 성장 표시가 현실의 변화와 연결된다고 느끼는가. 본인 사용 후 소규모 외부 시험으로 확인한다.

**제품 원칙:** 목표 달성을 위한 앱이 게임 숙제를 늘려서는 안 된다. 휴식과 재시작을 허용한다. 신수의 희귀성과 개체 차이는 재미를 주되 새 사용자와 일반 신수가 쓸모없어지지 않게 한다.

## 2. 대상 플랫폼과 범위

- 안드로이드 휴대폰/태블릿과 PC·모바일 웹을 동일 계정으로 사용한다.
- Android 홈 화면 위젯에는 대표 신수와 남은 퀘스트 수를 제안한다. 잠금화면 노출 방식은 기기·OS에 따라 조사/검증 후 정한다.
- iPhone은 이후 확장으로 둔다. 지금의 설계는 플랫폼을 추가할 수 있도록 한다.
- 한국어 우선. 밝은/어두운 테마는 같은 신수 자산을 쓴다.
- 온라인에서 로그인, AI 계획 생성, 뽑기, 파견 보상 확정, 동기화가 된다. 오프라인에서는 계획 확인과 퀘스트 완료를 임시 기록한 뒤 복구 시 동기화한다.

## 3. 첫 사용자 흐름

1. 가입·로그인.
2. 성향 설정: 시작이 어려운 편/꾸준한 편/많이 해도 괜찮은 편 중 사용자가 선택. 진단이나 의료적 분류로 취급하지 않는다.
3. 성장 목표를 자유롭게 입력. 현재 수준, 목표 시점, 선호 강도를 짧게 묻고 주당 가능 시간을 제안해 수정받는다.
4. AI가 강조점이 다른 **전체 로드맵 3개**를 제안. 예: 부담을 줄인 경로, 균형 경로, 집중 경로. 각 경로의 예상 일정·주당 시간·첫 주 행동을 비교한다. 사용자가 선택·수정한다.
5. 오늘 할 퀘스트 1~3개를 확인한다. 각 퀘스트에 쉬움/보통/도전 실행안을 둔다.
6. 태동 신수 3종 중 한 마리를 선택한다. 사용자가 목표를 먼저 만들고 신수를 고를지 순서는 화면 시안에서 비교한다.
7. 첫 퀘스트 완료 직후 신수의 짧은 반응, 목표 진행 기록, 첫 파견 안내를 보여준다.

**추가 목표:** 동시에 활성 목표는 최대 5개. 새 목표 생성이 필요하면 기존 목표를 보관할 수 있다. AI 무료 사용자의 새 목표 생성은 월 1회이며, 유료는 횟수 제한을 없애되 서버 남용 방지와 비용 한도를 둔다. AI가 만든 계획은 사용자가 수정 가능하다. 재작성은 사용자가 요청할 때만 한다.

## 4. 목표·퀘스트·진행 규칙

- 목표 → 로드맵 버전 → 단계(마일스톤) → 반복 습관 및 일회성 퀘스트 → 당일 실행 기록의 계층으로 보관한다.
- 로드맵 선택 시 첫 주만 구체적인 일일 행동으로 펼치고, 이후 주는 주간 점검/사용자 요청에 따라 상세화한다. AI가 한 번에 긴 계획을 만들어도 미래의 하루 일정을 고정하지 않는다.
- 기본 하루 퀘스트는 1~3개. 완료 후 `오늘 더 하기`로 추가할 수 있다. 사용자 설정으로 기본량을 늘릴 수 있다.
- 쉬움·보통·도전은 같은 목표를 향한 다른 수행량이다. 쉬움도 완료로 인정한다. 높은 강도는 보상을 조금 더 주되 무리한 수행을 요구하지 않는다.
- 기본 완료는 체크. 타이머·메모·사진은 선택. 사진 업로드는 별도 용량 정책이 필요하다.
- 휴식일, 미룬 날, 여행 등은 실패 벌점 대신 일정 재배치와 작은 재시작 퀘스트를 제안한다.
- 상태창은 단순 경험치와 함께 실제 증거를 보여준다: 완료한 단계, 누적 수행량, 첫날과 현재의 비교, 메모/결과물.
- 사용자는 수행 기록을 정정할 수 있다. 보상이 걸린 완료·취소는 서버의 거래 기록으로 중복 지급을 막는다.

## 5. 신수와 도감

- 첫 동료 3종 중 하나를 고른다. 종 후보는 미확정.
- 소유 개체는 중복을 포함해 최대 20마리. 활동 스쿼드는 그중 5마리. 종 도감은 과거에 만난 모든 신수를 영구 기록한다.
- 세 형태는 **태동 → 각성 → 초월**. 레벨과 현실 로드맵의 의미 있는 단계 달성이 진화 조건 후보. 진화 시 윤곽과 특징이 변하고 짧은 전환 연출이 나온다.
- 일반 레벨업과 진화가 주된 능력치 증가 경로. 추가 능력치 강화는 드문 별도 보상으로 설계한다.
- 개체값으로 같은 종 사이에 작은 차이를 둔다. 희귀 색 개체는 특별한 팔레트/효과와 작은 능력치 이점을 가진다. 격차 상한은 전투 모의실험 후 정한다.
- 장비는 없다. 외형 꾸미기는 오라·발밑 문양·배경 등으로, 전투 능력치와 분리한다.
- 도감의 50종은 후보 목록이다. 처음부터 50종의 태동/각성/초월 자산을 완성하는 것으로 간주하지 않는다. 전승을 참고한 종과 독자 창작 종을 구분하고 출처를 기록한다. 동양 용과 서양 용은 실루엣이 다른 계열이다.
- 20칸이 찼을 때 뽑기 결과가 사라지면 안 된다. 초과 결과는 수령함에 보류하고, 중복을 성장 자원으로 바꾸거나 기존 개체를 보관하는 결정을 사용자에게 받는 방안을 검토한다. 희귀 색/고개체값을 자동 처분하지 않는다.

## 6. 파견과 무료 뽑기

**파견형 모험 제안:** 스쿼드 5마리를 지역에 보내고 시간이 지나면 돌아온다. 사용자가 내내 앱을 켜 둘 필요가 없다. 현실 퀘스트를 하면 파견에 쓰는 활력이나 보상 보너스가 생긴다. 파견 자체는 짧은 편성 화면과 귀환 화면으로 끝난다.

- 지역에는 권장 전투력, 파견 시간, 예상 보상을 표시한다. 신수가 강해지면 더 높은 지역에 접근한다.
- 보상은 성장 재료, 꾸미기 재화, 뽑기권 조각 등이다. 조각을 모아 가끔 무료 뽑기를 한다.
- **강한 신수가 뽑기권을 좀 더 빨리 모은다.** 다만 파견 보상의 최저량과 속도 상한을 둬 격차가 무한히 커지지 않도록 한다. 새 사용자도 낮은 지역에서 꾸준히 뽑기권을 모을 수 있어야 한다.
- 퀘스트 강도를 무조건 높여야 좋은 파견을 보낼 수 있게 하지 않는다. 쉬움 완료도 파견 고리에 들어간다.
- 결과는 서버에서 확정한다. 기기 시계 변경·중복 수령·오프라인 재전송으로 보상이 반복되지 않도록 한다.
- 무료 뽑기는 확률과 보장/중복 처리 규칙을 공개한다. 구체적인 확률, 주간 획득 빈도, 천장 수치는 수집 시뮬레이션 후 결정한다.
- 뽑기 이외의 확정 획득 경로도 둔다: 첫 동료 선택, 단계 달성, 지역 첫 완료, 선택 가능한 조각 교환, 이벤트.

**미래 콘텐츠:** 탑은 스쿼드 편성과 성장의 도전장으로, 다른 사용자 스쿼드 열람과 비동기 대전은 선택형으로 설계한다. 사용자의 실제 목표·사진·메모는 기본 비공개다.

## 7. 화면 지도

1. 홈: 대표 신수, 짧은 반응, 오늘 남은 퀘스트, 목표 진행률, 파견 상태. 신수를 누르면 퀘스트 목록이 펼쳐진다.
2. 목표 만들기: 자유 입력 → 최소 질문 → AI 로드맵 3개 비교 → 선택/수정.
3. 로드맵: 단계·예상 시간·난도·근거/자료 펼치기·다시 설계하기.
4. 오늘의 퀘스트: 쉬움/보통/도전 선택, 체크, 선택형 타이머/메모/사진, 더 하기.
5. 상태창: 계정·목표별 실제 성장 지표, 첫날과 지금 비교.
6. 신수: 대표 신수, 5마리 스쿼드, 보유 개체 20마리, 도감, 진화와 꾸미기.
7. 파견: 지역 선택, 편성, 남은 시간, 보상 수령.
8. 뽑기: 무료 뽑기권, 확률·보장 규칙, 결과, 보유칸 초과 처리.
9. 설정: 계정, 동기화, 알림, 공개 범위, 데이터 내보내기/삭제, 구독.

메뉴 구조는 시안에서 3~5개의 주 탭으로 단순화한다. 모든 화면을 하단 탭에 넣지는 않는다.

## 8. 기술 설계 후보

**클라이언트:** Flutter 한 코드베이스로 Android와 웹을 개발하는 방안을 우선 검토한다. 신수 도트 이미지와 간단한 애니메이션을 공용으로 다룬다. Android 위젯·알림처럼 플랫폼 고유 기능은 별도 연동이 필요하다. 웹의 PC 레이아웃은 휴대폰 화면을 단순 확대하지 않고 넓은 화면에 맞춘다.

**백엔드:** Supabase의 인증, Postgres, 파일 저장소, 서버 함수를 후보로 둔다. 모든 개인 목표·진행 기록에는 사용자 단위 접근 규칙을 적용한다. AI 키, 뽑기 확률 계산, 파견 귀환 보상, 구독 확인은 클라이언트에 넣지 않고 서버에서 처리한다.

**AI:** 서버에서 OpenAI API를 호출하는 방안을 후보로 둔다. 사용자 입력 → 목표 확인 질문 → 서로 다른 3개 로드맵을 정해진 자료 구조로 생성 → 서버가 분량·날짜·실행 가능성·중복을 검사 → 사용자가 비교·수정한다. AI가 반환한 문장을 그대로 게임 보상 규칙에 사용하지 않는다. API 장애 시 기존 목표와 퀘스트는 계속 작동한다. 모델과 호출 비용은 구현 직전 다시 확인한다.

**주요 데이터:** 사용자/설정, 목표, 로드맵 버전, 단계, 습관, 당일 퀘스트, 완료 기록, 신수 종, 신수 개체, 도감 발견, 스쿼드, 파견, 게임 자원 거래 기록, 뽑기 기록, 꾸미기 소유, 구독 상태. 종/개체/도감은 분리해 중복과 희귀 색을 표현한다.

**동기화:** 오프라인 완료는 로컬 큐에 저장하고 요청별 고유 ID로 서버에 한 번만 반영한다. 경험치·파견 보상·뽑기는 서버 확정 후 표시한다. 여러 기기에서 같은 퀘스트를 완료해도 한 번만 지급한다. 사용자가 수정한 로드맵은 버전으로 보관한다.

## 9. 단계별 개발 로드맵과 완료 기준

| 단계 | 산출물 | 다음 단계로 갈 조건 |
|---|---|---|
| A. 제품 규칙 확정 | 3개 시작 신수, 퀘스트·성장·파견 수치표, AI 입력/출력 예시, 화면 흐름 | 목표 1개로 가입부터 첫 파견까지 설명이 막히지 않음 |
| B. 화면·아트 시안 | 홈/로드맵/퀘스트/신수/파견 시안, 태동→각성→초월 도트 1종 | 작은 화면·큰 화면에서 읽히고 신수 변화가 명확함 |
| C. 현실 성장 기능 | 계정, 목표, 로드맵 3안, 퀘스트, 완료/휴식/기록, 동기화 | 실제 목표를 2주간 써도 기록과 계획이 일관됨 |
| D. 신수 기본 고리 | 시작 선택, 5마리 편성, 성장/진화, 파견, 무료 뽑기, 도감 일부 | 중복 지급·보유칸 초과·기기 변경에도 결과가 보존됨 |
| E. 사용성 검증 | 본인 사용, 소규모 외부 시험, 재미/이탈 지점 수정 | 첫 목표와 첫 완료를 도움 없이 수행할 수 있음 |
| F. 공개 준비 | 운영·비용·로그·개인정보·결제/광고 여부·배포 준비 | 운영 예산 안에서 장애와 데이터 복구 절차를 확인함 |
| 이후 확장 | 50종 도감 확대, 탑, 공개 스쿼드, 비동기 대전, iPhone | 현실 성장 기능의 지속 사용을 확인한 뒤 진행 |

일정은 고정하지 않는다. 12월 중순 희망 시점은 범위를 결정할 때 참고하되, 각 단계의 완료 기준과 실제 제작량으로 공개 시점을 판단한다.

## 10. 지금 남은 핵심 결정

1. 첫 동료 3종과 첫 공개 시 완성할 신수 종수.
2. 20마리 보유칸의 초과 수령함·중복 전환 규칙.
3. 파견 지역·시간·보상량과 무료 뽑기 빈도의 시뮬레이션.
4. 개체값·희귀 색의 능력치 격차 상한, 진화 조건.
5. 첫 공개 범위에 파견·뽑기를 포함할지와 외부 시험 대상.
6. 구독과 광고의 실제 출시 시점, 꾸미기 상점의 판매 범위.
