## 2026-11-27 — 목표 동기화 충돌의 중간 변경 보호

- 충돌 해결에서 서버 기록을 선택했을 때 로컬 보관본 저장을 기다리는 사이 로그인 계정이 바뀌거나 사용자가 목표를 수정하면, 서버 목표를 기존 로컬 목표에 덮어쓰지 않게 했다. 가져오기 직전에 계정·목표 내용·활성 목표 수를 다시 확인한다.
- 두 상황 모두 수정 전 실패하는 재현 테스트를 추가했다. 목표 동기화 테스트 9개, Flutter 전체 280개 테스트와 정적 분석이 통과했다. 실계정 첫 업로드, Android·웹 충돌, 플립4 접힌 화면과 플립6 점검은 남았다.

## 2026-11-20 — 회원탈퇴 요청 본문 제한 보강

- `delete-account`가 JWT를 먼저 검증하고, `Content-Length`가 없거나 틀려도 실제 읽은 본문을 1024바이트에서 중단하도록 바꿨다. 정상 JSON·초과·잘못된 JSON·잘못된 UTF-8 단위 테스트와 외부 삭제 페이지 요청 테스트 **7개**가 통과했다. 운영 `mpj`에 함수 버전 **2**를 배포했고 `ACTIVE`, 무인증·위조 토큰 HTTP 401, 잘못된 메서드 405를 확인했다. 실제 인증 계정 삭제 시험은 여전히 남아 있다.
- 수동 목표 업로드의 서버 응답을 기다리는 동안 로그인 계정이 바뀌면 이전 계정의 동기화 기준본을 저장하지 않도록 보강했다. 변경 중 업로드를 재현하는 테스트를 추가해 Flutter 전체 **278개** 테스트와 정적 분석이 통과했다. Android arm64·웹 release 빌드를 갱신했다. 현재 [시험 APK](../growup-android-arm64.apk)는 `1.0.0+2018`, SHA-256 `D13007B417FCF06EAFCBBADB5DFF4E96E794B28EADBDCAE4EC32916C5F32C1E8`로 빌드 원본과 같고, [웹 압축본](../growup-web-release.zip)의 SHA-256은 `B4E5DE54C7408201A27CB60BDA834E67ED736755B810BE2C04DA8C48FA08F002`다. 플립4가 ADB에 보이지 않아 설치·실계정 확인은 남았다.
- 외부 삭제 페이지에서 OTP 요청 중 연결·서버 장애가 나면 인증번호 입력란을 열지 않고 재시도를 안내한다. 존재하지 않는 계정에 대한 응답은 등록 계정과 같은 문구로 유지했다.

## 2026-11-19 — 계정 삭제 서버 배포와 연쇄 삭제 검증

- 운영 `mpj` 프로젝트에 `delete-account` Edge Function을 배포했다. 함수 `ACTIVE` 버전 1, 무인증·위조 토큰 HTTP 401, 잘못된 메서드 405, 사전 요청 204를 확인했다. 로컬 PostgreSQL 11개 마이그레이션과 기능·동시성 테스트가 통과했고, 새 계정 삭제 검증에서 모든 `user_id` 테이블이 `auth.users`에 연쇄 삭제로 연결되며 목표·할 일·게임 행이 실제로 사라짐을 확인했다. 별도 시험 계정의 실제 삭제는 아직 확인하지 않았고 앱 회원탈퇴 플래그는 꺼져 있다.
- 설치 없이 이메일 인증번호로 요청하는 외부 계정 삭제 페이지와 공개 설정을 넣는 웹 빌드 스크립트를 만들었다. 삭제 요청이 계정을 새로 만들지 않도록 하고, 인증 세션 토큰은 저장하지 않는다. JavaScript 4개 테스트와 실제 CSS 폭 390px 화면에서 가로 넘침 없음을 확인했다. 당시 웹 배포 압축본의 SHA-256은 `D72BC9C78EA7B4007420918660DC9DFA5594BF19EAE303C1D437B9C3375877FB`다. 공개 HTTPS 게시와 실제 인증번호·삭제 검증은 남았다.
- 수동 목표 동기화를 Android·웹 시험 빌드에서 켰다. Flutter 전체 277개 테스트와 정적 분석, arm64 APK·웹 release 빌드가 통과했다. 당시 시험 APK `1.0.0+2017`의 SHA-256은 `A48AA0CCC61BD9E6DFC40F10F7D54165B56DF9AFDD90D05EC5207FEE94C311CA`로 빌드 원본과 일치했다. 현재 ADB에는 x64 에뮬레이터만 있어 플립4 설치·실계정 수동 동기화는 남았다.
- 출시 사전 점검 스크립트를 고쳐 영구 앱 ID, 업로드 키와 서명 값, 정책·외부 삭제 URL의 누락을 한 번에 보고한다. 값이 없는 현재 환경에서는 일곱 항목을 정확히 표시했고 임시 유효 형식의 값으로 통과 경로도 확인했다. 실제 업로드 키의 진위와 공개 주소 응답은 출시 전에 별도로 확인해야 한다.

## 2026-11-18 — 자갈도롱뇽 성장 모션·계정 도감·전투 재시도 복원

- 자갈도롱뇽의 태동·각성·초월에 각각 대기·눈 깜빡임·점프·착지 4프레임 투명 시트를 만들고 기기 전투에 연결했다. 첫 각성 시안의 불투명 몸체는 네 칸에서 크기·착지선이 같았으며 아주 옅은 알파 픽셀만 바깥에 남아 있었다. 태동·초월 시트도 같은 기준으로 검사했다. 시트별 그림 범위를 전투 표시 크기에 맞춰 잘라 그리고, Flutter 화면 미리보기에서 세 단계의 실제 외형을 확인했다. 별도 공격·피격·승리 그림은 아직 없다.
- 계정에만 있는 자갈도롱뇽은 도감에서 계정 최고 레벨의 외형을 보여준다. 계정 보유 개체 목록에는 단계·체력·공격·전투 경험을 기기 보유와 구분해 표시한다. 300dp·글씨 2배의 가짜 계정 화면에서 Lv 3 각성 외형, 체력 76·공격 18, 서버 스쿼드 2번 편성을 확인했다.
- 서버가 첫 승리 동료를 지급한 뒤 응답이 끊기면 재시도 결과에서 합류 정보가 빠지는 문제를 고쳤다. 새 DB 마이그레이션은 지급된 종을 같은 전투 시도에 기록하고 Edge 함수는 완료된 요청을 다시 읽을 때 이 값을 포함한다. 로컬 PostgreSQL의 11개 마이그레이션·기능·동시성 테스트에서 숲길 첫 동료, 강가 자갈도롱뇽, 반복 승리, 20마리 한도를 확인했다. 운영 `mpj`에 마이그레이션 11개가 일치하고 `verify-forest-battle` 함수 버전 3이 ACTIVE다. 무인증 호출은 HTTP 401이었다. 실제 계정의 응답 손실 재시도는 아직 재현하지 않았다.
- 2주 보상 경제 시뮬레이션에 서버 정식 전투권 +2장 청구·30장 상한을 반영했다. 보통 유형은 2주 뒤 전투권 28장이 남고, 많이 하는 유형은 미청구 완료가 쌓인다. 전투권 잔액이 29·30장이면 새 완료를 청구할 수 없으므로 화면에서 버튼을 막고 이유를 안내한다.
- Flutter 전체 테스트 **277개**, 정적 분석, 서버 JS 전투 계산 테스트, Android arm64·웹 release 빌드가 통과했다. 시험 [APK](../growup-android-arm64.apk)는 `1.0.0+2016`, SHA-256 `A0B2119D9C3ED58172028EA21AFB357E2500A0C214935D8D5FA8007DAE674E6D`로 빌드 원본과 일치한다. Galaxy Z Flip4에 업데이트 설치했고 버전 코드는 `4016`이다. 화면은 Dozing 상태라 이번 변경의 실기기 시각 확인은 남았다.

## 2026-11-17 — 안개 강가 계정 정식 전투 준비

- 서버의 전투 시도·증빙·첫 승리 원장이 강가 세 장소를 받아들이도록 열 번째 마이그레이션을 만들었다. 숲길 보스→강가 입구→물안개 여울→달빛 나루 순서를 서버에서 검사하고, 강가 첫 승리에는 조각 없이 배지를 기록한다. 여울 첫 승리에서 보유 20마리 미만인 계정에 레벨 3 자갈도롱뇽을 한 번 지급한다. 기존 숲길의 조각 1·1·2개와 성장 규칙은 유지했다.
- 전투 Edge Function의 장소 허용 목록과 앱의 강가 정식 전투 버튼·전적·보상·동료 표시를 확장했다. 실제 PostgreSQL 16의 마이그레이션 10개와 SQL 테스트·동시성 테스트, Dart/JS 전투 계산 비교, Flutter 전체 테스트 **265개**, 정적 분석을 통과했다. Android arm64와 웹 release 빌드도 통과했다.
- [시험 APK](../growup-android-arm64.apk)는 `1.0.0+2007`이며 SHA-256은 `44943405924EB68B0668D65CECA8D0EC6066EFB668B3F7219E25AD6EAF67A968`이다. 빌드 원본과 해시가 같다. 운영 `mpj` 프로젝트에 열 번째 DB 마이그레이션을 적용하고 전투 Edge Function을 재배포했다. 원격 이력 10개 일치, 함수 `ACTIVE`, 인증 없는 호출 HTTP 401을 확인했다. ADB에는 에뮬레이터만 있어 플립 계정의 실제 승리·보상·재실행은 확인하지 못했다.
- 강가 계정 전투 화면에 가짜 서버의 숲길 3개·강가 입구 첫 승리 기록을 넣어 물안개 여울만 열리고 달빛 나루는 잠긴 상태를 확인했다. 300dp·글씨 2배에서도 화면 예외가 없었다. Flutter 전체 테스트는 **266개 통과**했다. 실제 계정의 전투 요청은 기기가 연결되면 확인한다.
- 여울 첫 승리 직전에 계정 보유 신수가 20마리인 경우를 로컬 PostgreSQL 테스트에 추가했다. 첫 승리 배지와 전투권 소비는 기록되고 자갈도롱뇽은 21번째로 추가되지 않았다. 전체 SQL 마이그레이션·기능·동시성 테스트를 다시 통과했다.

## 2026-11-16 — 안개 강가 세 장소와 자갈도롱뇽

- 물안개 여울에 앞줄 공격 돌게와 후열 공격 갈대 추적자, 달빛 나루에 처음 피해 14 흡수·세 번째 행동마다 보호막 8 재생 보스를 추가했다. 세 장소에 각각 다른 배경·적 도트를 사용하고, 이전 장소 승리 후 다음 장소가 열린다. 기기 전투 별점·최저 턴과 숲길 진행도 3/3을 보존한다.
- 여울 첫 승리에서 자갈도롱뇽을 기기에 한 번 지급한다(20마리 한도). 태동·각성·초월 정지 그림, 도감·편성·전투와 세 번째 행동마다 피해 6 흡수 자갈 갑옷을 연결했다. 별도 모션 시트와 계정 보유는 남았다.
- Dart와 서버 JS 전투 결과 2,622개 편성 벡터가 일치했다. Flutter 전체 테스트 **264개 통과**, 정적 분석 문제 없음. Android arm64 APK `1.0.0+2006`과 웹 release 빌드가 통과했다. [시험 APK](../growup-android-arm64.apk)의 SHA-256은 `C051CCA8A757797B7034C7F277306920FE65A72AFFECF4108094FEA253852D6D`로 빌드 원본과 같다. 강가의 계정 정식 전투·서버 보상은 아직 연결하지 않았다.
- 에뮬레이터용 x86_64 APK도 빌드했으나 에뮬레이터 `/data` 여유 공간이 365MB여서 Android가 설치를 거부했다(`INSTALL_FAILED_INSUFFICIENT_STORAGE`). 사용자 앱 자료를 지우지 않았으며 화면 실행은 확인하지 못했다. 플립4·플립6은 이번 세션에 연결되지 않았다.

## 2026-11-16 — 안개 강가 첫 전투

- Dart와 서버 JS 전투 계산의 1,096개 편성 결과를 비교했다. 서버 장소 허용 목록, 보상 원장, 계정 정식 전투는 아직 강가에 연결하지 않았다. 물안개 여울·달빛 나루·신규 신수·실기기 화면 확인은 [안개 강가 계획](SECOND_REGION_PLAN.md)에 남긴다.
- Flutter 전체 테스트 **262개 통과**, 정적 분석 문제 없음. Android arm64 APK와 웹 release 빌드가 통과했고 시험 APK를 `1.0.0+2005`로 갱신했다. [APK](../growup-android-arm64.apk)와 빌드 원본의 SHA-256은 `AB23E041B84BC843FB7DE4DD85117A0D573055CE34E69AB4F1B91E77D6D65F14`로 일치한다. 무선 ADB에는 오프라인 에뮬레이터만 보여 실기기 설치·화면 확인은 하지 못했다.

## 2026-11-15 — 지난 실천 기록·계정 전투 기록·출시 준비

- 목표 기록 화면과 기록 달력의 선택 날짜에서 지난 MINI·MORE·MAX 실천을 새로 입력하거나 강도를 변경·취소할 수 있다. 최근 활동 행에서도 해당 날짜를 직접 수정한다. 미래 날짜와 목표 시작 전 신규 기록은 거부한다. 저장 후 XP·목표 통계·로드맵 연결 행동이 다시 계산된다. 훈련권 원장의 원천 ID는 목표·날짜로 고정되어 수정·취소·재입력해도 같은 날 중복 지급되지 않는다. 새 과거 기록의 최근 14일 훈련권은 게임 화면을 열 때 반영된다.
- 계정 정식 전투는 서버가 작성하고 소유자에게만 읽기 허용한 `game_battle_attempts`에서 장소별 최고 별과 최저 승리 턴을 각각 한 건씩 읽는다. 정식 전투 카드와 숲길 지도 상세에 기기 전투 기록과 구분해 표시한다. 서버 DB 스키마나 보상 지급 규칙은 변경하지 않았다. 계정 전환 시 이전 사용자의 기록을 숨긴다.

- Android 배포용 application ID·업로드 키 설정과 배포 모드 누락 검증을 추가했다. ID 변경 시 실제 MainActivity 클래스와 로그인 복귀 URI가 맞게 동작하도록 매니페스트와 Dart 설정을 연결했다. `내 데이터` 화면은 공개 정책·외부 삭제 URL이 제공되면 링크를 표시한다. [출시 준비 조건](RELEASE_PREP_2026_11_15.md)을 정리했다. 운영자 정보·실제 키·정책 게시·회원탈퇴 함수 배포는 남았다.

- 임시 ID `org.growup.testapp`으로 Android 디버그 매니페스트 병합을 시험해 package, 고정 MainActivity 클래스, 로그인 복귀 scheme이 각각 기대값으로 생성됨을 확인했다. 같은 ID에서 서명 값이 빠진 배포 모드는 빌드를 거부했다. 임시 ID는 공개 패키지명 결정이 아니다.

### 2026-11-11 · 참고 제품을 바탕으로 자율 개선

- Habitica의 현실 행동과 성장 연결, 기존 미니모어맥스 실천 원칙, 세븐나이츠 리버스의 편성 안내를 현재 제품 방향과 함께 검토했다. [선정 이유·사용 위치·화면·후속 우선순위](IMPROVEMENTS_2026_11_11.md)를 정리했다.
- 할 일 추가에 수정 가능한 루틴 예시 5개와 다음 반복 날짜 3개를 넣었다. 기존 할 일은 메뉴에서 반복·태그·작은 단계를 새 할 일로 복사할 수 있다. 완료·쉬기·이동·알림 이력과 보상 ID는 복제하지 않는다. 에뮬레이터에서 루틴 추가와 복사 후 미완료 항목 2개를 확인했다.
- 목표의 실천 카드에서 2·5·10·25분 집중 타이머를 열 수 있다. 일시 정지·재개·다시 정하기와 최근 한 세션의 기기 저장·복원을 추가했다. 에뮬레이터에서 2분 종료→MINI 선택→실천 기록, 백그라운드 중 경과, 강제 종료 뒤 실행 중 1:51 복원과 일시 정지 1:28 유지까지 확인했다. 타이머 자체는 완료나 보상을 생성하지 않는다.

[첫 알림](task-reminder-emulator.png), [재부팅 후 알림](task-reminder-reboot-emulator.png). 재부팅 후 예정 03:50 알림은 느슨한 예약 방식에 따라 03:52에 도착했다. 다음 알림을 예약한 뒤 스위치를 끄니 Android 알람 서비스가 예약을 취소했고 시험용 할 일을 삭제했다. 실기기의 알림 동작은 아직 확인하지 못했다.

### 2026-11-06 · 첫 숲길 신수 성장 단계 1차

- 기기 보유 신수의 전투 레벨로 태동·각성·초월을 판정한다. Lv 3/5 단계 전환에 작은 체력·공격 보너스를 더하고 예상 전투력과 실제 전투에서 같은 수치를 쓴다. 전투 결과에 이번 승리로 바뀐 단계를 표시한다.
- 서버 전투 계산도 같은 단계 보너스로 맞추고 경계 레벨을 포함한 편성·장소 822개 조합을 Dart·Node 양쪽에서 대조했다. 아직 서버 전투 API와 보상 증빙 연결은 준비되지 않았다.
- 도감에 개체별 현재 수치, 다음 단계까지 남은 경험, 세 단계 조건·보너스 비교를 넣고 단계에 따라 신수 주변 빛 고리를 다르게 그린다. 긴 상세 창의 닫기 버튼은 아래에 고정한다. [성장 단계 규칙](GAME_EVOLUTION.md)
- 최종 x64 출시 빌드를 에뮬레이터에 설치해 [도감 상세 화면](game-evolution-emulator.png)을 확인했다. 단계 비교 3개와 고정된 닫기 버튼이 화면 안에 보이고 스크롤할 수 있다.
- 보유 신수 목록에도 현재 성장 단계와 다음 단계까지 남은 전투 경험을 표시한다. 전체 Flutter 테스트 211개와 정적 분석, arm64 Android·웹 출시 빌드를 다시 통과했고 최신 APK를 플립4에 재설치했다.


### 2026-11-06 · 첫 숲길 도감의 획득 단서와 보유 개체

- 미발견 신수 카드에 획득 단서를 넣었다. 현재 시작 신수에 따라 이끼 문턱 첫 승리에서 확정 합류하는 종을 같은 게임 규칙 함수로 계산한다. 나머지 미발견 종에는 서버 기능 사용 가능 여부에 맞춰 정식 파견·무료 뽑기 경로를 안내한다.
- 발견한 종의 상세 화면에 기기 보유 개체별 레벨, 전투 경험, 편성 칸을 표시한다. 로그인한 계정의 서버 보유 종도 읽기 전용으로 도감 발견 수에 합치고 계정 개체의 레벨·편성은 따로 표시한다. 로그아웃하면 계정 발견 종이 사라지고 열려 있던 상세 창에서도 계정 종의 정보를 가린다. 320dp·200% 큰 글씨의 획득 단서, 중복 개체 2마리의 편성 위치, 서버 뽑기 후 도감 발견 수와 로그아웃 후 상세 정보 숨김을 위젯 테스트로 확인했다.
- 플립4는 무선 디버깅에는 연결되지만 접힌 커버 화면 상태여서 서버 첫 신수 등록 결과 및 이번 도감 화면은 아직 직접 확인하지 못했다.
- Android 에뮬레이터에서 새 도감 카드, 미발견 신수의 조각 안내, 파도수달 상세 창을 직접 확인했다. 좁은 화면에서 상세 창의 보유 수가 단어 중간에 줄바꿈되는 것을 발견해 기기·계정 보유 수를 별도 항목으로 나누고 계정 자료가 없으면 계정 수를 숨겼다. 새 x64 출시 빌드를 재설치한 뒤 [도감 화면](game-dex-emulator-check.png)과 [수정된 상세 화면](game-dex-detail-emulator-check.png)을 다시 확인했다.
- 최종 Flutter 테스트 208개와 정적 분석을 통과했다. 게임 서버·뽑기 옵션을 켠 Android arm64 및 x64 출시 APK와 웹 빌드가 성공했고, arm64 APK를 플립4에 기존 데이터 유지 상태로 다시 설치했다. 플립4는 접힌 커버 화면이므로 실제 계정의 도감 합산과 첫 신수 등록 결과 확인은 남았다.

### 2026-11-06 · 앱 설정에서 게임 효과 조정

- 계정 → 앱 설정의 `화면과 게임`에 전투 효과 줄이기와 전투 진동 스위치를 연결했다. 전투 화면에서 바꾼 값과 같은 기기 저장 값을 사용한다. Android의 진동은 기본 꺼짐이고 웹에는 진동 스위치를 표시하지 않는다.
- 320dp·200% 글씨에서 두 스위치를 켜고 새 게임 저장소로 읽어도 유지되는 위젯 테스트를 통과했다. 플립4는 접힌 커버 화면이라 설정의 실제 배치와 진동 체감은 아직 확인하지 못했다.
- 전체 Flutter 테스트 207개와 정적 분석, 서버 게임 기능을 켠 arm64 Android·웹 출시 빌드가 통과했다. 최신 APK를 기존 데이터를 유지하며 플립4에 설치했다.

### 2026-11-06 · 기술별 전투 연출과 결과 카드

- 전투 프레임에 기술 종류를 별도로 기록한다. 기본 공격, 솔여우 회복, 물수달 물결, 별까마귀 표식, 바람 그림자 돌풍, 새벽 파수꾼 공격에 각기 다른 색과 작은 도트 선·반짝임을 적용했다. 메시지 문자열만 보고 기술을 추측하지 않으며 전투 시뮬레이션에서 다섯 이름 붙은 기술의 분류를 확인했다.
- 승리·패배 결과를 색이 다른 카드로 정리하고 승리 별점 3칸을 아이콘으로 표시했다. 320dp·200% 글씨 화면을 포함한 전투 위젯 테스트에서 결과 카드와 별 개수를 확인했다.
- 회복 기술은 시전자와 실제로 체력이 오른 동료 모두에게 녹색 표시가 나타난다. 전투의 `효과 줄이기` 버튼은 배경 이동·신수/적 모션·도트 이펙트를 한꺼번에 멈추며, 기기 자체의 동작 줄이기 설정이 켜졌을 때는 별도 버튼을 숨긴다. 전투 중 켜고 다시 해제하는 위젯 테스트를 통과했다. 선택은 이 기기에 저장되어 다음 전투에도 적용되고 기기 기록 삭제 시 초기화된다.
- 선택형 전투 진동을 기본 꺼짐으로 추가했다. 전투 화면에서 켜면 행동 재생에 가벼운 진동, 승리에 결과 진동을 보내며 기기 동작 줄이기 설정에서는 보내지 않는다. 앱이 전면에서 벗어나면 전투 재생도 멈춰 배경 진동을 막는다. 기기 설정 저장·재시작·삭제와 꺼진 상태 무호출·백그라운드 정지·켠 뒤 행동/승리 호출을 자동 테스트했다. 실제 휴대폰의 진동 체감과 무음 모드 동작은 아직 확인하지 못했다.
- 플립4는 무선 ADB로 연결되지만 접힌 대기 상태라 첫 서버 신수 등록 결과 및 새 전투 화면은 아직 확인하지 못했다.
- 전체 Flutter 테스트 206개와 정적 분석, 서버 게임 기능을 켠 arm64 Android·웹 출시 빌드가 통과했다. 최신 APK를 플립4에 기존 데이터를 유지하며 설치했다. 설정 저장 중에는 같은 버튼을 잠시 비활성화해 빠른 연속 입력으로 저장 순서가 뒤바뀌지 않게 했다. 마지막으로 운영체제 동작 줄이기 설정이 켜진 경우에는 사용자가 진동을 켜 둔 상태여도 플랫폼 진동 호출이 발생하지 않음을 테스트했다.

### 2026-11-06 · 전투 도트 이펙트

- 전투 재생의 각 신수·적 스프라이트 위에 짧은 공격 궤적, 피격 표시, 승리 반짝임을 코드로 그렸다. 행동 프레임이 바뀔 때 이펙트를 다시 재생하며 운영체제의 동작 줄이기 설정에서는 표시하지 않는다. 작은 화면의 행 높이 안에 유지하고 색을 기존 전투 팔레트에 맞췄다.
- Flutter 렌더링 이미지에서 피격 표시가 크게 보이는 것을 확인해 선 길이를 줄였다. 임시 렌더링 테스트는 종료되지 않아 정리했으며 실기기 화면 품질은 아직 재확인이 필요하다. 전체 Flutter 테스트 201개가 통과했고 마지막 피격 크기 수정 후 전투·모션 관련 테스트와 정적 분석, Android arm64·웹 출시 빌드가 통과했다.
- 플립4의 무선 디버깅 연결이 새 주소로 복구되어 최종 APK 설치가 성공했다. 기기는 접힌 대기 상태였고 서버 첫 신수 등록·정식 파견 결과는 계속 미확인이다.

### 2026-11-05 · 전투 공격 방향과 실기기 서버 화면 확인

- 플립4에서 로그인 상태의 정식 파견 카드를 열어 실제 서버 조회 결과인 `서버 동료 없음 · 뽑기 조각 0개 · 오늘 0/3회`를 확인했다. 별까마귀 첫 등록 확인을 누른 직후 기기가 접혀 대기 상태가 되었으므로 등록 성공 여부는 아직 확인하지 못했다. 다음에는 카드를 새로고침해 등록 상태를 먼저 확인하고, 그 결과에 따라 정식 파견·귀환·뽑기를 진행한다.
- 전투의 신수가 위, 적이 아래에 놓이는 실제 배치에 맞춰 공격 동작을 신수는 아래로, 적은 위로 움직이게 고쳤다. 두 방향과 동작 줄이기 설정을 위젯 테스트로 확인했다. 솔여우 모션 시트의 1픽셀 차이로 소수점 경계가 생기지 않도록 네 프레임의 소스 범위를 정수 픽셀에 맞췄다.
- 기존 별까마귀 도트를 참조해 투명 배경 공격 자세를 생성하고 [D01 참고 이미지](concepts/star-crow-attack-concept.png)로 저장했다. 기존 게임 도트 시트와 픽셀 크기 및 묘사 밀도가 달라 출시 자산에는 적용하지 않았다.
- 마지막 수정까지 포함해 Flutter 테스트 200개, 정적 분석, 서버 게임 기능을 켠 arm64 출시 APK와 웹 출시 빌드가 통과했다. 최신 APK를 플립4에 기존 데이터를 유지하며 설치했다. 설치 성공은 확인했으나 기기가 접힌 잠금 상태여서 업데이트 후 화면과 첫 등록 결과는 아직 직접 재확인하지 못했다.

### 2026-11-05 · 전투 신수와 적의 동작 보강

- 전투 재생에서 신수가 공격·피격·승리·패배에 반응하게 했다. 적 도트에도 작은 대기 움직임과 공격·피격·패배 표시를 넣었다. 동작 줄이기 설정에서는 움직임을 멈춘다. 전투 기록에 행동한 편성 칸을 넣어 같은 종류가 두 마리여도 실제 행동자만 공격한다.
- 300dp 에뮬레이터에서 목표 예시 작성→MINI 완료→훈련권 획득→보스 전투 준비와 재생을 직접 진행하고 [피해·상대 배치 화면](game-battle-motion-emulator.png)을 확인했다. 이어 할 일을 완료해 훈련권 2회를 받아 새 적 동작이 포함된 빌드에서도 보스 전투를 재생했다. Flutter 테스트 200개와 정적 분석, 웹·x64·arm64 출시 빌드가 통과했다. 새 arm64 APK를 플립4에 기존 데이터를 유지하며 설치했다.
- 현재 공격·피격은 기존 4프레임 도트 시트의 화면 이동이다. 종별 공격·걷기 등의 별도 도트 프레임과 공통 캔버스 규격은 D01에 남겼다. 플립4가 잠금 상태여서 실제 계정의 서버 파견·뽑기는 계속 미검증이다.

### 2026-11-05 · 서버 게임 실동작 사전 점검

- 가짜 서버를 연결한 정식 파견 화면에서 첫 신수 등록, 하루 3회 출발·귀환, 조각 3개 획득, 무료 뽑기, 새 신수와 조각 잔액 표시까지 한 경로로 검증했다. 로그아웃 상태에서는 정식 파견 카드에서 계정 로그인으로 바로 이동할 수 있다. 300dp 에뮬레이터에서 [버튼의 글씨 대비](game-server-login-emulator.png)와 실제 로그인 화면 이동을 확인했다. 전체 Flutter 테스트 195개와 정적 분석이 통과했고 새 arm64 APK를 플립4에 기존 데이터를 유지하며 설치했다. 실제 계정의 파견·뽑기 결과 검증은 플립4 잠금 해제 뒤 남아 있다.

- 기존 목표는 저장 시각의 날짜를 시작일로 보여준다. 새 시작일은 목표 JSON 백업과 서버 목표 스냅샷에 포함한다. 이전 서버 스냅샷에 시작일 항목이 없을 때 불필요한 동기화 충돌이 생기지 않도록 빈 항목은 기록하지 않는다. 두 기기 실제 동기화 확인은 남았다.
- 할 일 추가·수정 창은 제목, 날짜·시간, 반복, 알림, 중요도·태그·목표 연결을 구분했다. 저장 전 선택한 일정이 입력창에 보이고 저장 후 목록에도 표시된다.
- 기록 달력 날짜 칸에는 MINI 파랑·MORE 초록·MAX 금색 점과 범례를 넣었다. 이번 달 기록 카드에는 날짜별 각 목표 실천과 완료한 할 일·메모를 펼쳐 보여준다. 빈 날짜는 중립색으로 표시한다.
- 전체 Flutter 테스트 233개와 정적 분석을 통과했다. 키보드가 올라온 320dp 화면에서도 할 일 저장 버튼이 보이고 동작함을 확인했다. 날짜 선택·할 일 입력·기록 달력은 300~411dp 화면 캡처로 배치를 확인했다. 자동 화면 캡처의 한글 글꼴은 사각형으로 렌더링되어 실제 한글 인상은 플립 기기에서 다시 봐야 한다.
- 최종 arm64 release APK를 growup-android-arm64.apk로 복사하고 Galaxy Z Flip4에 업데이트 설치했다. 앱 실행 프로세스를 확인했으며 최근 로그에 치명 오류가 없었다. 플립6에는 사용자가 같은 파일을 수동으로 업데이트 설치해야 한다.

# 2026-11-08 사용 피드백 U12·U13·U15 및 U14 일부

- 실천 카드의 상시 주간 수치·속도 문구를 제거하고 목표 상세보기에서 이번 주 진행률·기간을 확인하게 했다.
- MINI·MORE·MAX 버튼 세 개를 `완료하기` 하나로 줄였다. 선택 시 행동과 XP를 비교하는 시트가 열리고, 기존 완료·수정·훈련권 지급 로직을 그대로 사용한다.

- 로드맵은 매일 체크할 일이 아닌 목표 이정표라는 설명과 예시를 목표 상세에 넣었다. 목표 만들기에 `로드맵은 나중에 만들기` 선택을 추가했다. 카드 안의 단계 편집 동선과 자동 시작안 단순화는 U14에서 이어간다.

- arm64 release APK를 새로 빌드해 growup-android-arm64.apk에 복사했다. 이번에는 플립4 무선 ADB 연결이 끊겨 자동 업데이트 설치는 하지 못했다. 플립6에도 사용자가 APK를 수동 설치해야 한다.
