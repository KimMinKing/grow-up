# 계정·설정·데이터 관리

## 현재 시험 설치본

Galaxy Z Flip4에서 이메일 인증번호 로그인이 완료됐고, 업데이트 설치 후에도 세션이 복원되는 것을 확인했다. 계정 화면에는 이메일·가입일·표시 이름, 표시 이름 변경, 기록 백업, 앱 설정, 게임 안내, 데이터 저장 방식, 로그아웃, 회원탈퇴, 기기 기록 삭제가 있다.

계정 화면의 순서는 프로필 → 설정과 데이터 안내 → 계정과 기기 관리 → **맨 아래 백업**이다. 기록 화면에서도 백업은 맨 아래에 두었다.

- **표시 이름**은 Supabase 사용자 메타데이터에 저장한다. 이메일 주소 변경 기능은 아직 없다.
- **앱 설정**에서 어두운 테마, 완료 후 게임 보상 안내, 알림 조용한 시간과 Android 알림 권한을 다룬다. 할 일별 알림 시간은 해당 할 일에서 설정한다.
- **로그아웃**은 계정 세션만 종료한다. 기기 기록은 그대로 남는다.
- **이 기기 기록 삭제**는 `기록 삭제` 입력을 요구하며 기기의 목표·할 일·메모·게임 진행·앱 설정과 목표 동기화 체크포인트를 지운다. 현재 로그인 세션과 서버 데이터, 내보낸 JSON 백업은 유지된다. 앱이 저장한 키만 제거하므로 Supabase 세션 저장소를 전체 삭제하지 않는다.
- **회원탈퇴**는 `탈퇴` 입력을 요구하며 Supabase 인증 계정과 외래 키로 연결된 앱 데이터베이스 행을 삭제하도록 구현했다. 기기 기록과 사용자가 내보낸 백업은 유지된다. 별도 시험 계정의 실제 삭제가 검증되기 전에는 앱 버튼이 비활성화된다.

서버에서 지워지는 앱 데이터베이스 행은 `auth.users`를 참조하며 `ON DELETE CASCADE`로 연결된 목표 동기화, AI 사용량, 게임 파견·신수·뽑기·첫 승리 기록이다. 이미 발송된 이메일, 사용자가 다른 위치에 저장한 백업 파일, 서비스 제공자의 백업·로그까지 앱에서 삭제할 수 있다고 주장하지 않는다.

## 회원탈퇴 서버 함수

코드: [`supabase/functions/delete-account/index.ts`](../supabase/functions/delete-account/index.ts). 요청의 사용자 ID를 받지 않고 Bearer JWT를 Supabase Auth에서 검증해 호출자 본인의 계정만 삭제한다. 본인 이메일과 고정 확인값이 함께 맞아야 한다. 서버 전용 비밀 키는 함수 환경에만 둔다. `supabase/config.toml`의 해당 함수는 플랫폼의 기본 JWT 검증을 끄고 함수 안에서 사용자 JWT를 검증한다.

2026-11-20에 운영 `mpj` 프로젝트의 `delete-account`를 버전 2로 갱신했다. 함수는 `ACTIVE`이며 무인증·위조 토큰은 HTTP 401, 잘못된 메서드는 405, CORS 사전 요청은 204로 응답했다. 인증을 먼저 확인하고 요청 본문은 `Content-Length` 여부와 무관하게 실제 읽은 바이트를 최대 1024바이트로 제한한다. 로컬 PostgreSQL에서는 모든 `user_id` 앱 테이블의 `auth.users` 삭제 연쇄와 목표·할 일·게임 행 삭제를 확인했다. **인증된 별도 시험 계정의 확인값 거부·실제 삭제·재로그인 불가**는 아직 검증하지 않았으므로 시험 APK의 `ACCOUNT_DELETION_ENABLED`는 꺼 둔다. 실제 사용자 계정은 시험에 사용하지 않는다.

2026-11-19에 웹 출시본에 [외부 계정 삭제 페이지](../web/delete-account.html)를 추가했다. 앱 설치 없이 등록 이메일로 인증번호를 받아 본인 확인 후 같은 `delete-account` 함수에 삭제를 요청한다. OTP 요청에는 `create_user: false`를 넣어 삭제 요청이 새 계정을 만들지 않는다. 토큰은 브라우저 메모리에만 두고, 삭제 성공 시 지운다. `scripts/build_web_release.ps1`은 Flutter 웹 빌드 뒤 공개 Supabase URL·publishable key만 페이지 설정으로 기록한다. JavaScript 요청 테스트 4개와 웹 출시 빌드·정적 화면 확인을 마쳤다. **공개 HTTPS 호스팅, 실제 인증번호·삭제 흐름, 외부 URL과 앱 링크 연결은 아직 남았다.** 배포 빌드에 `PRIVACY_POLICY_URL`, `ACCOUNT_DELETION_URL`을 전달하며 외부 삭제 링크는 `ACCOUNT_DELETION_ENABLED=true`일 때만 표시한다. [출시 준비 현황](RELEASE_PREP_2026_11_15.md)

현재 외부 페이지는 실제로 사용 중인 이메일 인증 계정을 대상으로 한다. Google·Kakao 같은 소셜 계정 로그인을 켜기 전에는 그 계정의 외부 삭제 본인 확인 경로도 추가 검증해야 한다. 이메일 OTP의 동작은 [Supabase 공식 안내](https://supabase.com/docs/guides/auth/auth-email-passwordless)를 따른다.

## 공개 배포 전 남은 일

- 실제 운영 주체, 연락처, 보관 기간, 위탁 서비스와 문의·삭제 요청 경로를 확정해 정식 개인정보처리방침을 작성하고 앱 및 배포 페이지에 연결한다. 현재 화면은 저장 방식 안내이며 법적 문서가 아니다.
- 이메일 주소 변경은 Supabase의 확인 메일 동작과 재로그인 흐름을 실제 SMTP 환경에서 검증한 후 제공한다.
- 별도 시험 계정으로 잘못된 확인값 거부·삭제 후 재로그인 불가와 연결 데이터 삭제를 검증한 뒤 앱의 회원탈퇴 기능을 켠다.
- 계정 연동 범위는 현재 목표·실천 기록의 수동 동기화 코드에 한정된다. 할 일·메모와 로컬 게임 진행은 JSON 백업을 사용한다. 서버 게임 기능의 기록은 별도 서버 데이터다.
