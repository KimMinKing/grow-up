현재 구현과 검증 결과는 [작업 기록](PROGRESS.md), **바로 다음 작업과 막힌 조건**은 [TODO](../TODO.md)에 갱신한다. 이 문서는 전체 기능 범위와 개발 순서를 보존한다. [README](../README.md)에 실행 방법과 제한을 기록했다.

## 0. 한 문장 정의

이 앱은 **목표를 계획하고 꾸준히 실행하며 내 성장을 눈으로 확인하는 도구**다. 사용자가 원할 때만 별도의 신수 게임 공간으로 이동한다. 게임은 성장을 축하하고 즐기는 부가 기능이다.

## 1. 두 공간의 정보 구조

### 성장 공간: 앱을 열면 항상 여기서 시작

- 상단/모서리: `게임으로` 전환 버튼. 한 번의 터치로 이동하고 같은 위치에서 돌아온다. 마지막으로 보고 있던 성장 화면을 기억한다.
- 홈: **함께 성장하는 특별한 대표 신수 한 마리**, 오늘의 퀘스트 1~3개, 현재 목표의 진행률, 작은 성장 요약. 완료 버튼이 한눈에 보인다.
- 대표 신수 터치: 상태창, 레벨 변화, 최근 성취, 실제 성장 증거로 확장된다. 수집 신수와 달리 대표 신수는 사용자의 성장 여정을 끝까지 함께한다.
- 성장 공간 메뉴: `오늘`, `목표·로드맵`, `성장 기록`. 설정은 우측 상단. 게임 요소로 화면을 채우지 않는다.
- 목표 만들기: 짧은 입력 → 현재 수준·목표 시점·강도 → 주당 가능 시간 제안 → AI 로드맵 3개 비교 → 선택/수정 → 오늘의 작은 행동.
- 습관: 쉬움·보통·도전 중 그날 선택. 기본은 체크; 사진·타이머·메모는 선택. 휴식과 일정 조정 가능.
- 상태창: 게임식 레벨과 함께 실제 증거(완료한 단계, 누적량, 첫날과 현재 비교)를 보여준다. 실제 성취가 숫자보다 우선한다.

### 게임 공간: 원하는 사람만 진입

- 별도의 배경·메뉴를 가진 게임 화면. `성장으로` 버튼이 항상 눈에 보인다.
- 메뉴: `스쿼드`, `파견`, `도감`, `무료 뽑기`. 탑·대전은 후속 기능.
- 수집 신수는 최대 20마리 보유하고 그중 5마리를 편성한다. **대표 신수와 수집 신수는 별도 개념**이다.
- 태동→각성→초월, 레벨, 개체값, 조금 더 강한 희귀 색, 오라·배경 꾸미기를 게임 공간에서 다룬다. 장비는 없다.
- 게임에 들어가지 않아도 목표·습관·대표 캐릭터 성장은 완전하게 이용할 수 있다. 게임 알림도 별도 설정한다.

### 둘 사이의 연결

현실 퀘스트 완료 → 대표 캐릭터와 목표 기록이 먼저 갱신 → 게임을 사용하는 계정에만 파견 활력/성장 재료가 쌓임 → 5마리 스쿼드를 시간제 파견 → 귀환 보상으로 가끔 무료 뽑기. 강한 스쿼드가 조금 더 빨리 모으지만 기본 획득량과 상한을 둔다. 목표 5개를 만들거나 게임을 매일 열어야만 성장하는 구조는 피한다.

## 2. 첫 사용자 경험과 주요 시나리오

1. 가입/로그인 후 첫 목표를 자유 문장으로 적는다.
2. 짧은 맞춤 질문에 답한다. 현재 수준·목표 시점·선호 강도를 필수로, 주당 가능 시간은 제안값을 수정한다.
3. AI가 **전체 로드맵 3개**를 보여준다. 부담을 줄인 안, 균형 안, 집중 안처럼 비교 기준이 분명해야 한다. 각 안에 예상 기간, 주당 시간, 첫 주 행동을 표시한다.
4. 사용자가 선택·수정하고 첫 퀘스트를 시작한다. AI가 부적절하거나 불가능한 안을 만들면 직접 편집할 수 있다.
5. 첫 완료 직후 대표 캐릭터가 반응하고, 목표의 실제 진척이 기록된다. 게임 안내는 작게 한 번만 표시한다.
6. 사용자가 원할 때 `게임으로` 이동해 시작 신수 3종 중 하나를 고르고 첫 파견을 보낸다.
7. 며칠 뒤 다시 들어오면 오늘의 할 일이 먼저 보이고, 놓친 날이 있어도 작은 재시작을 제안한다.

**추가 시나리오:** 목표 수정/보관, 새 로드맵 생성, 하루 더 하기, 휴식일, 오프라인 체크와 재접속, 휴대폰과 PC 동기화, 중복 신수, 20칸이 찬 상태, 구독 만료, 계정 삭제. 각 시나리오의 화면과 데이터 처리는 구현 전에 표로 확정한다.

## 3. 핵심 규칙 초안

- 활성 목표: 최대 5개. 보관된 목표와 기록은 유지한다.
- 무료 AI: 월 1회 **새 목표의 로드맵 생성**. 유료는 횟수 제한을 없애되 합리적인 요청 속도 제한과 운영 예산 보호 규칙을 둔다. 사용자가 작성한 계획의 수동 수정은 무료.
- 오늘의 기본 퀘스트: 1~3개. `더 하기`로 추가 가능. 쉬움 수행도 완전한 성공이며 벌점은 없다.
- 대표 캐릭터의 레벨: 체크 횟수만으로 무한 증가하지 않게 일일 보상 상한을 둔다. 로드맵 단계 완료와 실제 결과물에 큰 비중을 둔다.
- 게임 신수: 중복 포함 20마리 보유, 스쿼드 5마리. 태동→각성→초월. 개체값·희귀 색의 격차는 작은 상한 안에서 검증한다.
- 파견: 시간 경과형. 서버가 시작·종료·보상을 확정한다. 신수가 강하면 상위 지역 또는 적당한 속도 보너스를 얻는다. 사용자의 기기 시계를 신뢰하지 않는다.
- 무료 뽑기: 파견 보상 등으로 얻은 뽑기권만 사용. 유료 뽑기 없음. 확률, 보장 횟수, 중복 처리, 보유칸 초과 처리는 시뮬레이션 후 정한다.
- 유료 후보: AI 구독, 광고 제거, 꾸미기 상품. 실제 결제와 광고는 첫 공개에 필요한지 별도 결정한다.

## 4. 이미지·화면 시안 범위

- **대표 신수 태동·각성·초월 수정 시안 3장 제작 완료:** [태동](../assets/concept/guardian-taedong-v2.png), [각성](../assets/concept/guardian-gakseong-v2.png), [초월](../assets/concept/guardian-chowol-v2.png). [아트 시안 기록](ART_CONCEPT.md)에 단계별 디자인 규칙을 남겼다. 생성 파일은 배경 투명 1312×1199 PNG이며 정식 64×64 도트 스프라이트가 아니다.
- 대표 캐릭터의 신수형 방향은 확정했다. 현재 여우·용 계열 시안의 외형과 밝은/어두운 테마의 배경 톤은 검토 대상이다.
- 우선 그릴 화면 시안은 성장 홈(모바일/PC), 로드맵 3안 비교, 퀘스트 완료·상태창, 게임 전환 화면이다. 신수 50종을 먼저 그리지 않는다.
- 신수 도트 아트 제작 규격(캔버스, 시점, 팔레트, 3단계 실루엣, 짧은 반응 프레임)은 게임 개발 단계 전에 별도 문서로 만든다.

## 5. 기술 선택: 가볍고 유지보수 쉬운 후보

### 권장안: Flutter로 확정해 화면 시제품 검증

- **웹·안드로이드 UI:** Flutter + Dart 한 코드베이스. 화면과 신수 연출의 일관성, 앱과 같은 전환 효과, 정교한 상태창을 우선한다. 성장 공간은 읽기 쉬운 텍스트와 입력폼을 먼저 설계한다.
- **안드로이드:** Flutter Android 앱으로 배포. 홈 화면 위젯 등 Android 고유 기능이 필요할 때만 작은 Kotlin 연동을 만든다. 초기에는 별도 게임 엔진을 넣지 않는다.
- **DB/계정/서버:** Supabase Free의 **PostgreSQL**을 개발·지인 시험에 사용한다. 인증, 데이터베이스, 서버 함수가 한곳에 있어 초기 운영이 단순하다. MySQL도 가능하지만 이 선택에서는 별도 인증·API 서버·호스팅 구성이 늘어난다.
- **AI:** 서버 함수에서 API를 호출하고 정해진 로드맵 자료 구조로 받는다. API 비밀키와 무료/유료 사용량 검사는 서버에 둔다.
- **오프라인:** 로컬 저장소에 목표·오늘의 퀘스트·미전송 완료를 캐시하고 재접속 시 동기화한다. 파견 귀환·뽑기·경험치 최종 보상은 서버가 확정한다.

### 선택 이유와 검증할 약점

화면과 캐릭터 연출의 퀄리티가 중요하고 더 큰 앱 크기를 허용한다는 요청에 따라 **Flutter를 우선 채택**한다. Flutter는 Android와 웹을 한 코드베이스로 지원하고 그래픽 중심의 독립 웹 앱에 적합하다. 웹은 별도 렌더링을 사용하므로 긴 로드맵 글, 입력폼, 첫 로딩의 사용성을 실제 화면 시제품에서 확인한다. 품질 기준을 충족하지 못하면 React/Capacitor 대안을 다시 검토한다. Android 위젯은 후속 네이티브 작업으로 잡는다.

Supabase는 PostgreSQL이다. **Free는 $0이며 500MB DB와 인증 등을 제공하지만 활동이 적으면 약 1주 후 프로젝트가 일시 정지될 수 있다.** 지인 시험에는 적합한 후보지만 안정적 공개 운영 전에는 요금·백업·사용량을 다시 계산한다. Pro는 현재 월 $25부터다. OpenAI API 비용, 도메인, 앱 배포 비용은 별도이며 실제 사용량을 관찰해 월 10만 원 운영 목표에 맞춘다. Free의 자동 백업 부재를 감안해 시험 단계에서도 정기 데이터 내보내기를 계획한다.

## 6. 데이터 설계: 테이블 초안

| 구역 | 주요 데이터 | 주의점 |
|---|---|---|
| 계정 | users, profiles, preferences, subscriptions | 공개 설정과 알림 설정 분리 |
| 성장 | goals, roadmap_versions, milestones, habits, task_instances, completions, progress_snapshots | 로드맵을 수정해도 과거 기록 보존 |
| 대표 캐릭터 | avatar_progress, avatar_visual_state | 현실 성장과 직접 연결 |
| 게임 | creature_species, creature_instances, collection_log, squads, expeditions, rewards, draws, cosmetics | 종과 보유 개체 구분, 20칸 제한 |
| 운영 | currency_ledger, ai_usage, sync_operations, audit_events | 중복 지급 방지와 비용 추적 |

DB의 사용자별 행 접근 정책을 적용한다. AI 생성, 파견 결과, 뽑기 결과, 결제 상태는 클라이언트가 임의로 수정하지 못하게 서버에서 처리한다. 오프라인 완료에는 고유 요청 ID를 붙여 여러 기기에서 재전송돼도 한 번만 반영한다.

아래는 전체 개발 순서의 원안이다. 실제 완료 상태와 당장 할 일은 [TODO](../TODO.md)와 [작업 기록](PROGRESS.md)을 기준으로 한다.

### A. 제품 규칙 확정

1. 성장 공간과 게임 공간의 사용자 목적을 한 문장씩 확정한다.
2. 대표 캐릭터는 특별한 신수형으로 확정하고 수집 신수와의 관계를 정의한다.
3. 성장 공간의 첫 화면에서 보일 정보와 게임 전환 버튼 위치를 결정한다.
4. 가입부터 첫 퀘스트 완료까지 사용자 흐름을 그린다.
5. 목표 입력 질문의 필수/선택 항목을 확정한다.
6. AI 로드맵 3개의 차별화 규칙과 비교 항목을 확정한다.
7. 목표 수정·보관·삭제와 활성 목표 5개 제한을 정의한다.
8. 퀘스트의 쉬움/보통/도전, 휴식, 더 하기, 기록 정정 규칙을 정의한다.
9. 대표 캐릭터의 레벨과 실제 성장 지표의 관계를 정의한다.
10. 게임 진입·이탈과 게임 기능을 사용하지 않는 계정의 흐름을 정의한다.
11. 5마리 스쿼드·20마리 보유·중복·초과 수령함 규칙을 정의한다.
12. 파견 시간/지역/보상, 강한 신수의 보너스 상한을 정한다.
13. 무료 뽑기 빈도, 확률, 보장, 중복 처리를 시뮬레이션해 정한다.
14. 태동→각성→초월 조건, 개체값, 희귀 색 능력치 범위를 정한다.
15. 초기 공개에 포함할 기능과 이후 확장 기능을 확정한다.

**완료 기준:** 종이 위에서 목표 하나의 생성부터 2주 사용과 첫 파견까지 모순 없이 설명할 수 있다.

### B. 디자인·콘텐츠 시안

16. 성장 공간과 게임 공간의 시각 규칙을 각각 정한다.
17. 제작된 대표 신수 콘셉트 시안 3장을 검토하고 앱에서 쓸 형태로 규격화한다.
18. 성장 홈의 모바일/PC 화면을 그린다.
19. 로드맵 3안 비교와 편집 화면을 그린다.
20. 퀘스트의 세 강도 선택·완료·휴식 화면을 그린다.
21. 상태창의 실제 성장 증거와 레벨 표시를 그린다.
22. 게임 전환, 스쿼드, 파견, 도감의 간단한 화면 흐름을 그린다.
23. 글자 크기·대비·터치 영역·화면 읽기 기준을 정한다.
24. 시안을 작은 Android 화면과 PC 화면에서 검토한다.

**완료 기준:** 사용자가 두 공간을 헷갈리지 않고, 성장 홈에서 오늘 할 일을 바로 찾는다.

### C. 프로젝트와 데이터 기반

25. Flutter 저장소, 코드 구조, 환경별 설정, 형식 검사와 빌드 명령을 마련한다.
26. 웹 앱 골격과 Android 포장 골격을 구성한다.
27. 개발용 PostgreSQL/Supabase 프로젝트와 DB 변경 이력 체계를 만든다.
28. 계정/목표/로드맵/퀘스트/대표 캐릭터 테이블을 만든다.
29. 게임 테이블은 확장 가능한 최소 골격만 만들고 초기 성장 흐름을 복잡하게 하지 않는다.
30. 사용자별 접근 규칙과 서버 비밀키 보관을 설정한다.
31. 데이터 내보내기와 복구 절차를 마련한다.
32. 개인정보·목표 텍스트·사진 저장 범위와 보존/삭제 규칙을 정한다.

**완료 기준:** 다른 계정의 목표를 읽거나 수정할 수 없고, DB를 비워 다시 만들어도 변경 이력으로 복원할 수 있다.

### D. 성장 공간 기본 기능

33. 가입·로그인·로그아웃·세션 복구를 만든다.
34. 첫 목표 입력과 맞춤 질문을 만든다.
35. AI 호출 없이 수동 목표/로드맵 생성 흐름부터 만든다.
36. 목표 수정·보관·활성 5개 제한을 만든다.
37. 로드맵 단계와 주간·당일 퀘스트를 만든다.
38. 쉬움/보통/도전 선택과 완료·취소·기록 수정을 만든다.
39. 휴식일·미룸·재시작·오늘 더 하기를 만든다.
40. 누적량·단계 완료·첫날 대비 변화의 계산을 만든다.
41. 대표 캐릭터의 세 임시 시안과 레벨 반응을 연결한다.
42. 밝은/어두운 테마, PC/태블릿/휴대폰 배치를 정리한다.

**완료 기준:** AI와 게임 없이도 목표를 만들고 2주간 실천·수정·복귀할 수 있다.

### E. AI 로드맵

43. 목표 상담용 질문과 로드맵 출력 자료 구조를 정한다.
44. 질이 다른 목표 예시로 AI 결과를 검토할 평가표를 만든다.
45. 서버 함수에 AI 호출, 인증, 월 사용량 검사, 비용 기록을 넣는다.
46. 전체 로드맵 3개를 만들고 기간·강도·실행 가능성을 검사한다.
47. 결과 비교, 선택, 수동 수정, 저장을 연결한다.
48. 사용자 요청으로 재설계할 때 이전 버전과 기록을 보존한다.
49. AI 오류·지연·예산 한도 도달 시 수동 계획으로 계속 진행하게 한다.
50. 운동·건강 등 민감한 목표에서 과도한 권고가 나오지 않도록 검토한다.

**완료 기준:** 사용자가 세 안을 비교해 선택하고 첫 주 퀘스트를 시작하며, AI 실패에도 기존 기록이 손상되지 않는다.

### F. 계정 동기화·오프라인

51. 웹과 Android에서 같은 계정으로 같은 목표·기록이 보이는지 확인한다.
52. 오프라인에서 오늘 목록과 완료 기록을 임시 저장한다.
53. 재접속 시 완료 요청을 한 번만 반영한다.
54. 두 기기에서 같은 퀘스트를 완료·수정했을 때 충돌 규칙을 적용한다.
55. 동기화 중/실패/완료 상태를 사용자에게 알린다.
56. 시간대 변경과 날짜 경계, 주간 반복 규칙을 검증한다.

**완료 기준:** 네트워크가 끊겨도 체크를 잃지 않고, 여러 기기에서 경험치가 중복 지급되지 않는다.

### G. 게임 공간 첫 버전

57. 성장 공간과 분리된 게임 메뉴와 복귀 버튼을 만든다.
58. 시작 신수 3종과 임시 도트 자산을 확정한다.
59. 종·개체·도감 기록을 분리해 구현한다.
60. 20마리 보유, 5마리 편성, 교체, 중복 처리를 만든다.
61. 태동→각성→초월, 레벨, 개체값, 희귀 색 계산을 만든다.
62. 대표 캐릭터 성장과 게임 보상 사이의 연결을 만든다.
63. 1개 지역의 시간제 파견을 먼저 만든다.
64. 서버에서 파견 종료와 보상을 확정하고 중복 수령을 막는다.
65. 여러 지역·권장 전투력·보상 상한을 추가한다.
66. 무료 뽑기권 조각, 뽑기, 보장 기록을 추가한다.
67. 20칸 초과 수령함과 확인 후 중복 전환을 만든다.
68. 오라·배경 꾸미기와 짧은 캐릭터 반응을 추가한다.

**완료 기준:** 목표 퀘스트 → 파견 → 귀환 → 무료 뽑기 → 편성이 한 바퀴 돌고, 게임에 들어가지 않는 계정도 성장 기능을 정상 사용한다.

### H. Android 편의 기능

69. Android 앱의 설치·로그인·뒤로 가기·알림 동작을 확인한다.
70. 대표 캐릭터와 남은 퀘스트 수의 홈 화면 위젯을 검토·구현한다.
71. 잠금화면 표시 가능 범위는 지원 기기에서 직접 검증한다.
72. 알림은 사용자가 고른 상황(여유 시간, 오래 미룸, 파견 귀환)별로 켜고 끄게 한다.
73. 저사양 기기에서 이미지 크기, 첫 실행, 애니메이션을 점검한다.

**완료 기준:** 앱을 열지 않아도 필요한 정보는 확인할 수 있으며 알림이 지나치게 잦지 않다.

### I. 본인·지인 시험과 운영 준비

74. 실제 목표 하나로 2주 이상 사용하면서 막히는 지점을 기록한다.
75. 지인에게 설명 없이 첫 목표와 첫 퀘스트를 만들어 보게 한다.
76. 목표 달성률보다 시작·복귀·계획 수정의 편리함을 우선 평가한다.
77. 신수 성장과 뽑기가 목표 수행을 돕는지, 방해하는지 확인한다.
78. 접근성, 로그인 복구, 계정 삭제, 데이터 내보내기를 점검한다.
79. AI 사용량·DB 크기·파일 저장량·서버 함수 비용을 측정한다.
80. 오류 기록·서비스 상태 확인·백업 및 복구 연습을 한다.
81. 개인정보 처리 문서, 배포 등록, 등급·결제·광고 적용 요건을 공개 범위에 맞춰 확인한다.
82. Android 설치본과 웹 배포본을 같은 데이터로 최종 확인한다.

**완료 기준:** 목표 하나를 실제로 진행하며 데이터가 보존되고, 운영 비용을 예측할 수 있다.

### J. 시험 결과 뒤의 확장

83. 도감과 도트 신수를 지역별로 늘린다. 50종은 장기 후보 규모다.
84. 무한의 탑을 추가한다.
85. 선택형 공개 스쿼드와 비동기 대전을 검토한다.
86. 꾸미기 상점·AI 구독·광고 제거의 실제 효용과 비용을 검증한다.
87. iPhone 지원을 검토한다.

## 8. 바로 다음 설계 산출물

코딩 전에 다음 네 문서/시안이 완성돼야 한다: (1) 성장 공간과 게임 공간의 화면 흐름도, (2) 대표 캐릭터 3장 시안과 UI 목업, (3) 목표·퀘스트·대표 레벨의 수치표, (4) 파견·뽑기·개체값의 경제 시뮬레이션. 그 뒤에 기술 후보를 작은 화면으로 시험하고 최종 확정한다.

## 9. 확인할 결정

- 수정한 대표 신수(여우·용 계열) 도트풍 시안의 외형과 색을 그대로 이어갈지, 조정할지?
- 정식 아트에서는 태동→각성→초월의 **크기·몸 비율·자세** 차이를 v2보다 더 크게 만든다. 태동과 각성이 비슷해 보인다는 사용자 피드백이 있다.
- 태동·각성·초월을 정식 64×64 또는 96×96 격자 스프라이트로 바꿀 때의 크기와 동작 범위는?
- 지인 시험 첫 버전에 게임 공간은 `전환 버튼+준비 화면`까지만 둘지, `첫 파견과 무료 뽑기`까지 넣을지?
