# 게임·할 일 관리 벤치마킹과 확장 설계

2026-11-02 조사. 사용자 요청의 “하비카”는 Habitica로 해석했다. 이 문서는 **이미 있는 기능**, **참고할 구조**, **전설키우기에 적용할 제안**을 구분한다. 실제 구현 대기열은 [TODO.md](../TODO.md)의 「게임·할 일 관리 확장 대기열」을 따른다. 세븐나이츠의 고유 캐릭터·화면·음악·수치와 Habitica의 고유 디자인은 복제하지 않는다.

Habitica의 체력 손실과 동료에게 피해가 가는 벌칙은 이 앱의 핵심 경험과 맞지 않는다. 쉬기·미완료·재시작은 처벌 없이 기록하고, 게임 보상은 **완료한 행동**에 붙인다. 세븐나이츠의 장비 체계와 유료 뽑기도 기존 [제품 청사진](PRODUCT_BLUEPRINT.md)에 따라 도입하지 않는다. 아래의 전투·경제 수치는 모두 **새 제안**이며 벤치마킹 게임의 규칙이라는 뜻이 아니다.

## 목표 사용자 흐름

1. 오늘 화면에서 **해야 할 일**을 날짜·시간·반복 여부와 함께 확인한다. 시간이 없으면 2분짜리 첫 단계로 쪼갤 수 있다.
2. 완료하면 그 일의 기록이 남고, 대표 신수 반응·훈련권 등 **실제 받은 것**이 한 번만 표시된다. 체크를 잘못했다면 취소와 보상 정정 규칙이 분명하다.
3. 원할 때 게임으로 가서 훈련권을 사용하거나, 준비된 5마리 스쿼드로 지도 스테이지에 도전한다. 전투 전 적·권장 역할·예상 보상을 확인한다.
4. 짧은 전투의 행동·피해·승패가 보이고, 첫 클리어 보상과 다시 도전할 때의 보상이 구분된다. 보상으로 신수를 얻거나 키워 다음 스테이지를 공략한다.
5. 게임을 열지 않은 날에도 할 일·기록·목표는 정상 작동한다. 며칠 쉬었다 돌아오면 밀린 일을 다시 정리할 수 있으며 게임 진행을 잃지 않는다.

## 기능별 설계 기준

### 할 일 관리

- 작업 종류는 **일회성 할 일**, **반복 루틴**, **목표의 MINI·MORE·MAX 실천**을 내부적으로 구분한다. 사용자가 추가할 때는 먼저 제목만 적고 날짜·반복·하위 단계는 필요할 때 펼친다.
- 할 일의 `예정 날짜`, `시각`, `완료 날짜`, `반복 규칙`을 구분한다. 자정을 넘거나 시간대를 바꿔도 완료 기록이 중복되지 않게 한다.
- 반복 루틴의 매 회차는 별도 완료 ID를 갖는다. 같은 회차의 체크 취소·재완료는 보상을 중복 생성하지 않는다. 안 한 회차를 몰아서 체크해 재화를 얻는 허점은 제한한다.
- 한 일을 여러 단계로 쪼개도 **보상은 작업 단위**로 계산한다. 하위 항목을 한꺼번에 만들어 훈련권을 무한히 얻는 일을 막는다.
- 예정일이 지난 일은 지워지지 않는다. `오늘 하기`, `날짜 바꾸기`, `작게 나누기`, `보관`을 제공한다. 쉬기·미완료에 체력 피해를 주지 않는다.
- 알림은 사용자 선택 기능이다. 날짜·시간 알림, 조용한 시간, 반복 알림을 제공하되 기본값으로 과도한 알림을 보내지 않는다.
- 달력의 하루에는 해야 할 일과 완료한 일을 구분해 보여준다. 월간 보기뿐 아니라 오늘·이번 주 목록을 제공하고, 목표·태그·상태로 검색한다.
- “내가 정말 하고 싶은 보상”은 선택 항목으로 검토한다. 실제 소비를 강요하거나 실천 실패를 벌점으로 바꾸지 않는다.

### 현실 행동과 게임 보상의 연결

- 일회성 할 일, 반복 루틴의 한 회차, MINI·MORE·MAX, 로드맵 단계 완료의 보상을 표로 정한다. 서로 다른 종류의 완료가 같은 원장을 통해 **한 번만** 지급되게 한다.
- 훈련권 2회 지급은 현재 임시 규칙이다. 하루 보상 상한, 쉬운 일 여러 개로 쪼개기, 완료 취소·삭제·복원, 백업 가져오기, 두 기기 동시 완료를 시뮬레이션한 뒤 수치를 확정한다.
- 이미 써 버린 훈련권의 원본 체크를 취소했을 때는 잔액을 음수로 만들지 않는다. 회수 가능한 잔액만 회수하거나 조정 내역을 남기는 규칙을 먼저 확정한다.
- 보상 화면은 무엇 때문에 몇 개를 받았는지, 다음 보상까지 얼마나 남았는지 보여준다. 게임을 쓰지 않는 사람에게는 불필요한 수치·팝업을 숨긴다.

### 완전한 첫 게임 순환

- 첫 지역은 `지도 → 적/보상 미리 보기 → 5칸 편성 → 짧은 자동 전투 → 결과 → 성장/수집 → 다음 스테이지`로 만든다. 현재 3개 장소의 읽기·클리어 화면은 이 구조의 임시 뼈대다.
- 전투는 신수의 역할·속성·기본 공격·액티브 스킬·간단한 상태 효과가 실제 결과에 영향을 주게 한다. 전투 로그, 체력바, 1배·2배 속도, 연출 건너뛰기, 패배 이유를 제공한다.
- 진형은 처음에 전열·후열 한 가지 규칙만 검증하고, 같은 신수를 옮겼을 때 피격과 공격이 달라지는 것을 화면과 테스트로 확인한다. 이후 다른 진형을 늘린다.
- 스테이지는 `고유 ID, 지역/장, 선행 스테이지, 적 구성, 권장 전투력, 입장 비용, 첫 클리어 보상, 반복 보상, 기록`을 갖는다. 보스 스테이지는 외형·행동·보상으로 일반 스테이지와 구분한다.
- 보상은 `첫 클리어 확정 보상`과 `반복 획득 보상`을 나눠 설계한다. 중복 수령·기기 시계 조작·재접속 후 재시도에 안전한 서버 확정이 필요하다.
- 두 번째 신수를 **확정적으로** 얻는 초반 경로가 먼저 있어야 5칸 편성이 의미를 갖는다. 그 뒤 무료 뽑기·조각·도감 보상을 붙인다. 유료 뽑기는 계획하지 않는다.
- 신수 레벨업·진화·희귀 색·오라·배경은 차례로 넣는다. 장비 없이도 성장 차이가 전투와 외형에 나타나야 한다.
- 대기·걷기·공격·피격·승리·패배 도트 모션의 크기·프레임·기준점을 통일하고, 저사양·큰 글씨·작은 화면에서 전투 UI가 겹치지 않게 한다.

## 구현 순서와 완료 조건

| 순서 | 묶음 | 완료 조건 |
|---|---|
| A | 할 일 날짜·반복·하위 단계와 오늘/이번 주 정리 | 날짜를 옮기거나 앱을 재시작해도 회차·완료 기록이 보존된다. 할 일만 쓰는 사람도 빠르게 처리한다. |
| B | 완료 보상 원장과 경제 수치 | 취소·재완료·백업·두 기기 동시 완료에서 한 행동이 중복 보상되지 않는다. 2주 사용 시 보상 부족·과잉을 점검한다. |
| C | 첫 지역 전투 세로 구간 | 첫 스테이지를 준비→전투→승리/패배→보상→다음 스테이지까지 실제로 진행한다. 패배 뒤 편성을 바꿔 재도전할 수 있다. |
| D | 신수 획득·육성·지역 확장 | 시작 직후 두 번째 신수를 확정 획득하고 5칸 스쿼드를 키우며 첫 지역을 끝까지 클리어한다. |
| E | 연출·안내·동기화·실기기 검증 | 설명 없이 오늘 할 일 1개 완료부터 첫 보상·모험까지 진행할 수 있고, 재설치·백업·두 기기에서도 기록이 어긋나지 않는다. |

완료 기준은 기능 개수가 아니라 **현실 할 일 하나를 끝낸 결과가 게임 안에서 이해 가능하고, 게임을 한 번 끝낸 보상이 다음 현실 행동을 방해하지 않는 것**이다. 사용자에게 추가 과제를 강요하는 로그인 보상·과한 일일 숙제·연속 기록 끊김 벌점은 우선순위에 넣지 않는다.
